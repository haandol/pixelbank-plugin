# 결정 변경 이력: distribution

[English](decision-log.md)

독립 배포 패키지의 주요 결정 변경을 최신순으로 기록한다. 현재 유효한 요구사항과 근거는 해당 ADR에 함께 보존한다.

## 2026-11-14 — 로컬 action을 등급별 도구에 넣은 다섯 노출 도구

- **Current ADR**: [Bun 기반 플러그인 설치와 배포](./0001-bun-plugin-runtime.md)
- **Change type**: 요구사항 규칙 변경
- **What**: 묶음 원격 도구와 별도의 로컬 연결·연결 해제·크레딧 페이지·업로드·작업공간 열기·대기 도구 → 정확히 다섯 도구. 네 원격 등급 도구에 대기와 작업공간 열기를 읽기 action으로, 이미지 업로드를 편집 action으로 넣고, 로컬 연결 도구 하나가 연결·연결 해제·크레딧 페이지 열기 action을 가진다. 로컬 action의 describe는 로컬에서 답하고 전체 목록에 로컬 action을 포함한다. 예전 이름은 알 수 없는 도구 대신 대체 도구를 알려 주는 폐기 거부로 처리한다. INVALID_ARGUMENTS 인수 거부는 아무 작업도 시작되지 않았다고 안내하고 INVALID_INPUT은 쓰기 가능성 안내를 유지한다.
- **Why**: 서비스가 권한 등급마다 도구 하나와 필요 시 인수 스키마 조회로 목록을 줄였고, 사용자는 호스트가 등급마다 한 번 승인하도록 어시스턴트에게도 같은 다섯 도구를 보여 주기로 했다.

## 2026-11-14 — 로컬 도구가 감싸는 원격 조회 숨김

- **Current ADR**: [Bun 기반 플러그인 설치와 배포](./0001-bun-plugin-runtime.md)
- **Change type**: 요구사항 규칙 변경
- **What**: 어시스턴트가 보는 목록을 업로드 티켓·소스 저장을 뺀 모든 원격 도구 → 작업공간 조회와 워크플로 상태 조회까지 뺀 묶음 원격 도구로 바꾼다. 두 조회는 로컬 작업공간 열기와 제한된 대기의 내부 조회로 남는다. 이미 끝난 실행의 대기는 바로 반환하고, 안내는 작업별 도구 대신 묶음 도구와 action 이름을 사용한다.
- **Why**: 원격 서비스가 어시스턴트 문맥을 줄이려고 작업을 권한 등급별로 묶었고, 사용자가 기능마다 하나의 노출 진입점을 두기로 했다.

## 2026-11-12 — 자동 산출물 동기화를 별도 작업으로 연기

- **Current ADR**: [Bun 기반 플러그인 설치와 배포](./0001-bun-plugin-runtime.md)
- **Change type**: 요구사항 규칙 변경
- **What**: 실시간 입력 검증과 제한된 대기는 유지하고 자동 내보내기·저장소 동기화는 이번 구현에서 제외한다.
- **Why**: 사용자가 워크플로의 배포 준비를 먼저 마무리하고 자동 내보내기는 ADR만 남기기로 했다.

## 2026-11-12 — 실시간 계약 검증과 제한된 워크플로 대기

- **Current ADR**: [Bun 기반 플러그인 설치와 배포](./0001-bun-plugin-runtime.md)
- **Change type**: 아키텍처와 요구사항 규칙 변경
- **What**: 원격 호출 전달에 최신 목록 기반 입력 검증, 공개 계약 동기화와 읽기 전용 워크플로 대기를 추가한다. 기존 Bun 설치와 발행 경계는 유지한다.
- **Why**: API 변경마다 별도 스키마를 손으로 고치지 않고 입력을 맞추며, 오래 실행되는 작업을 다시 제출하지 않고 진행 상황을 확인하기 위해서다.
