# ADR 0001: Bun 기반 플러그인 설치와 배포

[English](0001-bun-plugin-runtime.md)

Date: 2026-11-07

## Status

Proposed

## Purpose

PixelbankStudio Plugin 사용자는 어시스턴트가 로컬 MCP 연결 프로그램을 시작하기 전에 필요한 실행 환경을 알아야 한다. 기여자는 같은 프로그램을 하나의 지원 런타임으로 빌드하고 검증할 수 있어야 한다. 사용자는 플러그인 실행과 개발 전반에 Bun을 사용하고, Bun이 없는 사용자에게 설치 방법을 안내하기로 했다.

이 결정은 독립적으로 배포하는 데스크톱 플러그인의 실행 환경과 배포 요구사항, 그리고 브리지가 어시스턴트에게 보여 주는 원격·로컬 도구 범위를 소유한다. 계정 권한, 창작 처리, 크레딧과 묶음 원격 도구 구성은 PixelbankStudio 원격 서비스가 소유한다.

브리지가 노출하는 도구 정의는 모두 어시스턴트의 문맥을 차지하며, 호스트는 승인과 읽기 전용·파괴적 처리를 인수 단위가 아니라 도구 단위로 정한다. 원격 서비스는 작업을 권한 등급별 네 도구로 묶고 action으로 작업을 고르며, 요청하면 작업의 정확한 인수를 알려 준다. 사용자는 PixelbankStudio 도구를 이 네 도구와 로컬 연결 도구 하나, 정확히 다섯 개만 보여 주기로 했다. 로컬 기기가 필요한 작업은 도구를 늘리지 않고 같은 권한 등급의 원격 도구에 더해지므로, 기능마다 어시스턴트가 보는 진입점은 하나이고 해당 등급의 승인을 따른다.

## Decision Drivers

- 고객의 필수 실행 환경과 기여자의 검증 환경은 같은 런타임 계열을 사용해야 한다.
- 설치된 플러그인은 실행 의존성을 포함해 사용자가 런타임 설치 후 실행할 수 있어야 한다.
- 실행 환경 통일은 기존 인증·파일 보호·발행 검증을 보존해야 한다.
- 영어와 한국어 사용자에게 동등한 설치·복구 안내를 제공해야 한다.
- 어시스턴트는 호스트가 권한 등급별로 따로 승인할 수 있는 다섯 도구에서 기능마다 하나의 진입점만 본다.
- 어시스턴트는 아무 작업도 시작되지 않아 고쳐서 다시 보내도 되는 인수 거부와, 쓰기가 이미 반영되었을 수 있는 결과를 구분할 수 있어야 한다.

## Decision

PixelbankStudio Plugin의 데스크톱 실행, 의존성 준비, 빌드와 검증에 Bun을 사용한다. 고객은 Bun을 먼저 설치한다. 독립 설치 패키지는 실행 번들, 스킬, 공개 도구 계약과 필수 고지를 포함한다.

개발과 자동 검증은 같은 기록된 Bun 버전을 사용한다. 지원 데스크톱 환경은 macOS와 Linux다. 기존 MCP와 비공개 파일 처리는 Bun의 호환 표준 라이브러리 API를 사용할 수 있으며, 런타임 선택으로 원격 서비스의 권한을 변경하지 않는다.

### 실시간 목록, 공개 계약과 노출 목록

인증된 원격 목록이 현재 도구의 사용 가능 여부와 입력 스키마를 결정한다. 브리지는 호출을 전달하기 전에 현재 노출된 인수 개요로 인수를 검증하고 서비스는 action마다 정확한 스키마로 다시 검증하며, 스키마 파일이 기능이나 권한을 부여하지 않는다. 패키지의 공개 도구 계약은 기존 수동 관리 절차를 통해 오프라인 조회와 재현 가능한 릴리즈를 지원한다. OpenAPI 자동 내보내기와 저장소 간 동기화는 별도 작업으로 미룬다. 현재 워크플로 도구의 실행과 입력 검증은 이 자동화를 요구하지 않는다. 공개 빌드는 비공개 체크아웃이 필요 없으며 공개 산출물이 실행 권한을 부여하지 않는다.

어시스턴트는 PixelbankStudio 도구를 정확히 다섯 개 본다. 권한 등급마다 하나인 원격 읽기·편집·삭제·실행 도구와, 연결·연결 해제·크레딧 페이지 열기 action을 가진 로컬 연결 도구다. 브리지는 원격 도구의 주석, 설명, action 목록과 인수 개요를 그대로 전달하고, 로컬 작업을 같은 등급의 원격 도구에 더한다. 워크플로 실행 대기와 준비된 작업공간 열기는 읽기 도구에, 선택한 로컬 이미지 하나의 업로드는 편집 도구에 들어간다. 로컬 action은 해당 도구의 action 목록에 짧은 인수 개요와 함께 나타나고, 도구의 주석을 따르며, 브리지 안에서 실행되고 서버로 전달되지 않는다. 로컬 action은 원격 도구와 필요한 내부 조회가 모두 제공될 때만 더하며, 로컬 도구나 action 이름을 이미 포함한 원격 목록은 거부한다.

원격 action은 action과 인수를 바꾸지 않고 전달한다. 브리지는 예전 도구 이름을 변환하거나 별칭으로 되살리지 않는다. 예전 작업별 이름이나 로컬 도구 이름은 로컬에서 폐기된 도구로 거부하고, 현재 목록으로 알 수 있으면 새 도구와 action을 알려 준다. 그 밖의 알 수 없는 이름은 알 수 없는 도구로 거부한다. 어느 경우도 서버로 보내지 않는다. 업로드 티켓, 소스 저장, 작업공간 조회와 워크플로 상태 조회 도구는 내부용이다. 브리지는 이 도구들을 로컬 업로드, 작업공간 열기와 워크플로 대기에 사용하지만 목록에 노출하거나 직접 호출을 전달하지 않는다.

읽기 도구의 describe 작업은 로컬 action에 대해서는 브리지가 직접 답한다. 원격 요청 없이 해당 action의 정확한 인수 스키마, 필수 항목과 권한을 반환한다. 원격 action의 describe는 그대로 전달한다. action 없이 describe하면 요청을 전달하고, 서버 목록에 노출된 로컬 action과 연결 action마다 한 줄 요약을 더해 다섯 도구의 모든 action을 하나의 목록으로 보여 준다. 연결 action의 describe도 로컬에서 답한다.

인수 거부는 아무 작업도 시작되지 않았으며 고친 호출을 다시 보낼 수 있다고 안내한다. 서비스는 이런 거부를 실패한 인수 위치와 도구·action을 담은 INVALID_ARGUMENTS로 알리며, 브리지는 형식이 올바른 힌트를 유지하고 로컬 action의 인수를 거부할 때도 같은 코드를 쓴다. 도메인 규칙에 따른 INVALID_INPUT 거부와 분류되지 않은 거부는 쓰기가 이미 반영되었을 수 있으니 명시적으로 재시도하기 전에 확인하라는 안내를 유지한다.

서버가 대응하는 상태 조회를 제공하면 브리지는 읽기 전용 워크플로 대기를 제공한다. 대기 범위는 1–60초, 기본 30초이며 일반 조회 사이에 최소 5초를 두고 서버의 더 긴 간격과 재시도 거부 시간을 따른다. 대기 취소나 만료는 접수된 서버 실행을 계속 유지하고, 같은 실행 식별자와 마지막 관측 상태를 보존한다. 이미 끝났거나 실행 중이 아닌 실행은 첫 상태 조회 후 기다리지 않고 바로 반환한다. 조회가 쓰기 작업으로 바뀌지 않는다.

포함된 창작 워크플로 안내는 다섯 도구와 action 이름을 사용하고, action과 `arguments` 인수 객체로 호출하는 방식과 호출 전 describe를 설명하며, action별 동의 단서를 유지한다. 유료 작업 전에는 견적을 확인하고, 작업 키와 승인한 최대 크레딧을 유지하며, 명시적인 삭제 요청이 있을 때만 삭제를 확인하고, 진행 상황은 대기 도구로 확인한다.

### Requirement contract

#### 설치

| 필수 보장 | 관찰할 결과 |
| --- | --- |
| 지원하는 macOS·Linux 설치는 Bun으로 플러그인을 실행하며 Node.js 설치를 요구하지 않는다 — 승인된 실행 환경 범위. | Bun이 있고 Node.js가 없는 지원 기기에서 플러그인이 시작되고 기존 MCP 상호작용을 완료한다. |
| 설치 패키지는 실행 의존성을 포함한다 — 기존 독립 배포 계약. | 개발 체크아웃 밖에 복사한 패키지가 별도 의존성 설치 없이 시작된다. |
| 영문·한글 설치 안내는 Bun이 없을 때의 설치, 버전 확인과 호스트의 실행 파일 탐색을 설명한다 — 사용자의 명시적 요구. | 어느 언어로 읽어도 실행 환경 부재에서 실행 파일 확보와 플러그인 실행까지 진행할 수 있고, 서로의 언어로 이동할 수 있다. |

#### 검증과 발행

| 필수 보장 | 관찰할 결과 |
| --- | --- |
| 의존성 준비·타입 검사·빌드·테스트는 Bun으로 실행하며 검증 버전을 하나로 기록한다 — 승인된 개발 도구 범위. | Node.js 실행 파일이 설치되지 않은 새 검증 환경에서 전체 검사를 완료한다. |
| 런타임과 산출물 변경은 인증, 인증 정보 비공개 저장, 선택 파일 보호와 지원 프로토콜 동작을 보존한다 — 기존 플러그인 보장. | 설치 번들에서 기존 성공·거부 조건이 계속 성립한다. |
| 배포는 서드파티 고지와 번들·공개 계약의 무결성 확인을 유지한다 — 기존 릴리스 계약. | 배포물에 필수 고지가 있고 기록된 무결성 정보와 일치하며 재빌드 결과가 재현된다. |
| 발행 전 컨테이너 검증과 소스에 일치하는 검증 기록을 요구한다 — 기존 발행 경계. | 검증되지 않았거나 소스가 다른 트리는 발행할 수 없다. |

#### 실패 보장

| 필수 보장 | 관찰할 결과 |
| --- | --- |
| Bun이 없으면 문서에 안내한 사용자 설치 단계로 해결하며 플러그인이 런타임을 자동 설치하거나 조용히 다른 런타임으로 전환하지 않는다. | 런타임이 없는 시작 시도는 소프트웨어 설치, 인증 정보 변경이나 대체 프로세스 실행 없이 실패한다. |
| 호환되지 않는 런타임, 검사 실패 또는 달라진 재빌드 결과에는 성공한 검증 기록을 발급하지 않는다. | 문제를 수정하기 전에는 해당 후보를 검증된 산출물로 발행할 수 없다. |

#### 노출 목록

| 필수 보장 | 관찰할 결과 |
| --- | --- |
| 연결된 목록은 원격 읽기·편집·삭제·실행 도구와 로컬 연결 도구, 정확히 다섯 PixelbankStudio 도구를 보여 준다 — 승인된 목록 범위. | 네 원격 도구가 모두 있는 연결된 목록에 이 다섯 이름만 있고 다른 PixelbankStudio 도구는 없다. |
| 연결되지 않은 목록은 로컬 연결 도구만 보여 주고 원격 요청을 보내지 않는다 — 기존 연결 경계. | 연결되지 않은 목록에는 연결 도구만 있으며 서비스로 아무 요청도 가지 않는다. |
| 연결 도구의 action은 연결, 연결 해제와 크레딧 페이지 열기이며 다른 인수를 받지 않는다 — 승인된 로컬 도구 구성. | 각 action은 action만으로 실행되고, 추가 인수·인증 정보·URL은 로그인·폐기·페이지 열기 전에 거부된다. |
| 대기와 작업공간 열기는 읽기 도구의 action으로, 이미지 업로드는 편집 도구의 action으로 개요와 함께 나타나며, 원격 도구와 내부 조회가 제공될 때만 나타난다 — 승인된 등급 배치. | 워크플로 상태가 있으면 읽기 도구에 대기가, 업로드 티켓이 있으면 편집 도구에 업로드가 나타나고, 그렇지 않으면 나타나지 않는다. |
| 로컬 action은 브리지에서 실행되며 원격 action으로 전달되지 않는다 — 로컬 작업 경계. | 대기, 작업공간 열기와 업로드는 대응하는 내부 조회나 업로드 요청만 보내고, 로컬 action 이름의 원격 호출은 보내지 않는다. |
| 원격 목록은 로컬 도구나 action을 대체하거나 가릴 수 없다 — 신뢰하는 로컬 제어. | 연결 도구나 로컬 action 이름을 이미 포함한 목록은 거부되고 원격 호출이 일어나지 않는다. |
| 업로드 티켓·소스 저장·작업공간 조회·워크플로 상태 조회 도구는 목록에 없고, 직접 호출하면 로컬에서 거부한다 — 승인된 목록 범위. | 내부 도구 이름으로 호출하면 원격 요청, 작업이나 과금 없이 알 수 없는 도구로 거부된다. |
| 이미 완료·실패했거나 실행 중이 아닌 실행을 기다리면 최신 상태를 바로 반환한다 — 상태 조회를 숨기기 위한 사용자 요구. | 이런 대기는 상태를 한 번 조회하고 멈추지 않으며 끝난 이유를 알려 준다. |
| 원격 action은 action과 인수를 바꾸지 않고 전달한다 — 서비스가 소유한 원격 구성. | 원격 action 호출은 같은 도구, action과 인수로 서버에 도달한다. |
| 예전 도구 이름은 로컬에서 폐기된 도구로 거부하고, 알 수 있으면 새 도구와 action을 알려 주며, 별칭으로 동작하지 않는다 — 승인된 폐기. | 예전 로컬 이름이나 작업별 이름으로 호출하면 대체 도구를 알려 주는 폐기 거부가 반환되고 원격 요청은 없다. |
| 로컬 action의 describe는 정확한 인수 스키마와 권한을 로컬에서 답한다 — 승인된 필요 시 스키마 조회. | 이런 describe는 원격 요청 없이 브리지가 실제로 적용하는 것과 같은 스키마를 반환한다. |
| action 없는 describe는 다섯 도구의 모든 action을 한 줄 요약과 함께 보여 준다 — 승인된 필요 시 스키마 조회. | 목록에 서비스의 action과 노출된 로컬 action이 모두 있고 아무것도 바뀌지 않는다. |
| 인수 거부는 아무 작업도 시작되지 않았음을 알리고 위치·도구·action 힌트를 유지하며, 도메인 거부는 쓰기 가능성 안내를 유지한다 — 승인된 거부 구분. | INVALID_ARGUMENTS 거부는 고쳐서 다시 보내도록 안내하고, INVALID_INPUT 거부는 쓰기가 이미 반영되었을 수 있다고 경고한다. |
| 포함된 안내와 공개 문서는 다섯 도구, 그 action과 로컬 action만 영어와 한국어로 함께 설명한다 — 기존 이중 언어 문서 계약. | 어느 언어로 읽어도 같은 도구와 action을 설명하며, 숨겨진 이름이나 예전 이름을 호출 가능한 도구로 안내하지 않는다. |

## Alternatives

### Node.js로 통일

기존 런타임과 테스트가 함께 동작한다. 익숙한 필수 실행 환경을 유지하지만 사용자가 선택한 Bun 기반 실행·개발 환경을 충족하지 않는다.

### Bun 실행과 Node.js 개발 도구 병행

전환 범위를 줄이고 기존 테스트 실행기를 유지할 수 있다. 대신 두 런타임 환경이 필요하고 설치·빌드·검증 방식이 나뉜다.

### 작업공간 조회와 워크플로 상태 조회를 계속 노출

어시스턴트가 작업공간이나 실행 상태를 직접 조회할 수 있다. 두 조회는 이미 로컬 열기와 대기로 사용할 수 있으므로, 노출하면 목록 크기가 늘고 같은 조회에 진입점이 둘이 된다. 사용자는 숨기기로 했다.

### 로컬 작업마다 별도 로컬 도구

연결, 업로드, 작업공간 열기, 대기와 크레딧 페이지가 각각 별도 도구였다. 도구마다 어시스턴트 문맥에 정의가 하나씩 늘고 권한 등급과 무관한 승인 결정이 생긴다. 작업을 같은 등급의 원격 도구에 더하면 도구가 다섯 개로 유지되고 호스트가 읽기, 편집과 연결을 따로 승인할 수 있다.

## Consequences

고객은 플러그인을 활성화하기 전에 Bun을 설치하며, 기여자는 같은 런타임 계열로 개발과 검증을 진행한다. 실행 의존성을 번들에 포함하므로 의존성 준비는 발행자가 담당한다.

작업공간 조회와 워크플로 상태 조회를 숨기면 어시스턴트는 로컬 대기와 열기로만 이 조회를 사용한다. 상태 도구가 없는 서버에서는 대기도 제공하지 않는다. 변경 후에는 예전 로컬 제어를 포함해 예전 도구 이름에 저장된 호스트 승인이 더 이상 맞지 않으므로 호스트가 다시 확인을 요청한다. 읽기 도구를 승인하면 대기와 작업공간 열기도, 편집 도구를 승인하면 선택한 파일 업로드도 함께 승인된다. 브리지는 로컬 action을 더하기 위해 서비스의 describe 목록과 action 목록 형식에 의존하므로, 이 형식이 바뀌면 브리지 릴리스를 함께 맞춰야 한다.

유지보수자는 런타임에 따른 테스트 주입과 번들링 차이를 처리하면서 기존 검증 조건과 고지를 보존해야 한다. Bun 버전을 올릴 때 메타데이터·문서·검증을 함께 맞춘다. 시작 시간과 초기 메모리는 호환성·설치 부담과 함께 관찰할 수 있는 지표이며 합격 기준값으로 사용하지 않는다.
