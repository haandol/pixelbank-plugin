# ADR 0001: Bun 기반 플러그인 설치와 배포

[English](0001-bun-plugin-runtime.md)

Date: 2026-11-07

## Status

Proposed

## Purpose

PixelbankStudio Plugin 사용자는 어시스턴트가 로컬 MCP 연결 프로그램을 시작하기 전에 필요한 실행 환경을 알아야 한다. 기여자는 같은 프로그램을 하나의 지원 런타임으로 빌드하고 검증할 수 있어야 한다. 사용자는 플러그인 실행과 개발 전반에 Bun을 사용하고, Bun이 없는 사용자에게 설치 방법을 안내하기로 했다.

이 결정은 독립적으로 배포하는 데스크톱 플러그인의 실행 환경과 배포 요구사항, 그리고 브리지가 어시스턴트에게 보여 주는 원격·로컬 도구 범위를 소유한다. 계정 권한, 창작 처리, 크레딧과 묶음 원격 도구 구성은 PixelbankStudio 원격 서비스가 소유한다.

브리지가 노출하는 도구 정의는 모두 어시스턴트의 문맥을 차지한다. 원격 서비스는 작업을 권한 등급별로 몇 개의 도구로 묶고 action으로 작업을 고른다. 원격 작업공간 조회와 워크플로 상태 조회는 이미 설치된 브리지가 계속 동작하도록 남아 있으며, 로컬 작업공간 열기와 제한된 워크플로 대기가 이미 이 기능을 제공한다. 사용자는 이 두 조회를 어시스턴트에게서 숨겨 기능마다 어시스턴트가 보는 진입점을 하나만 두기로 했다.

## Decision Drivers

- 고객의 필수 실행 환경과 기여자의 검증 환경은 같은 런타임 계열을 사용해야 한다.
- 설치된 플러그인은 실행 의존성을 포함해 사용자가 런타임 설치 후 실행할 수 있어야 한다.
- 실행 환경 통일은 기존 인증·파일 보호·발행 검증을 보존해야 한다.
- 영어와 한국어 사용자에게 동등한 설치·복구 안내를 제공해야 한다.
- 어시스턴트는 기능마다 하나의 진입점만 본다. 묶음 원격 도구와 로컬 제어를 보여 주고, 로컬 도구가 이미 감싸는 원격 조회는 보여 주지 않는다.

## Decision

PixelbankStudio Plugin의 데스크톱 실행, 의존성 준비, 빌드와 검증에 Bun을 사용한다. 고객은 Bun을 먼저 설치한다. 독립 설치 패키지는 실행 번들, 스킬, 공개 도구 계약과 필수 고지를 포함한다.

개발과 자동 검증은 같은 기록된 Bun 버전을 사용한다. 지원 데스크톱 환경은 macOS와 Linux다. 기존 MCP와 비공개 파일 처리는 Bun의 호환 표준 라이브러리 API를 사용할 수 있으며, 런타임 선택으로 원격 서비스의 권한을 변경하지 않는다.

### 실시간 목록, 공개 계약과 노출 목록

인증된 원격 목록이 현재 도구의 사용 가능 여부와 입력 스키마를 결정한다. 브리지는 호출을 전달하기 전에 현재 계약으로 인수를 검증하며, 스키마 파일이 기능이나 권한을 부여하지 않는다. 패키지의 공개 도구 계약은 기존 수동 관리 절차를 통해 오프라인 조회와 재현 가능한 릴리즈를 지원한다. OpenAPI 자동 내보내기와 저장소 간 동기화는 별도 작업으로 미룬다. 현재 워크플로 도구의 실행과 입력 검증은 이 자동화를 요구하지 않는다. 공개 빌드는 비공개 체크아웃이 필요 없으며 공개 산출물이 실행 권한을 부여하지 않는다.

브리지는 묶음 원격 도구를 action 선택자, action별 인수, 주석과 설명까지 그대로 전달한다. 예전 작업별 도구 이름을 변환하거나 별칭으로 되살리지 않는다. 업로드 티켓, 소스 저장, 작업공간 조회와 워크플로 상태 조회 도구는 내부용이다. 브리지는 이 도구들을 로컬 업로드, 작업공간 열기와 워크플로 대기에 사용하지만 목록에 노출하거나 직접 호출을 전달하지 않는다. 로컬 연결, 업로드, 작업공간 열기와 크레딧 페이지 제어는 이름과 인수를 그대로 유지한다.

서버가 대응하는 상태 조회를 제공하면 브리지는 읽기 전용 워크플로 대기를 제공한다. 대기 범위는 1–60초, 기본 30초이며 일반 조회 사이에 최소 5초를 두고 서버의 더 긴 간격과 재시도 거부 시간을 따른다. 대기 취소나 만료는 접수된 서버 실행을 계속 유지하고, 같은 실행 식별자와 마지막 관측 상태를 보존한다. 이미 끝났거나 실행 중이 아닌 실행은 첫 상태 조회 후 기다리지 않고 바로 반환한다. 조회가 쓰기 작업으로 바뀌지 않는다.

포함된 창작 워크플로 안내는 묶음 도구와 action 이름을 사용하고, action과 같은 이름의 인수 객체로 호출하는 방식을 설명하며, action별 동의 단서를 유지한다. 유료 작업 전에는 견적을 확인하고, 작업 키와 승인한 최대 크레딧을 유지하며, 명시적인 삭제 요청이 있을 때만 삭제를 확인하고, 진행 상황은 대기 도구로 확인한다.

### Requirement contract

#### 설치

| 필수 보장 | 관찰할 결과 |
| --- | --- |
| 지원하는 macOS·Linux 설치는 Bun으로 플러그인을 실행하며 Node.js 설치를 요구하지 않는다 — 승인된 실행 환경 범위. | Bun이 있고 Node.js가 없는 지원 기기에서 플러그인이 시작되고 기존 MCP 상호작용을 완료한다. |
| 설치 패키지는 실행 의존성을 포함한다 — 기존 독립 배포 계약. | 개발 체크아웃 밖에 복사한 패키지가 별도 의존성 설치 없이 시작된다. |
| 영문·한글 설치 안내는 Bun이 없을 때의 설치, 버전 확인과 호스트의 실행 파일 탐색을 설명한다 — 사용자의 명시적 요구. | 어느 언어로 읽어도 실행 환경 부재에서 실행 파일 확보와 플러그인 실행까지 진행할 수 있고, 서로의 언어로 이동할 수 있다. |

#### 검증과 발행

| 필수 보장 | 관찰할 결과 |
| --- | --- |
| 의존성 준비·타입 검사·빌드·테스트는 Bun으로 실행하며 검증 버전을 하나로 기록한다 — 승인된 개발 도구 범위. | Node.js 실행 파일이 설치되지 않은 새 검증 환경에서 전체 검사를 완료한다. |
| 런타임과 산출물 변경은 인증, 인증 정보 비공개 저장, 선택 파일 보호와 지원 프로토콜 동작을 보존한다 — 기존 플러그인 보장. | 설치 번들에서 기존 성공·거부 조건이 계속 성립한다. |
| 배포는 서드파티 고지와 번들·공개 계약의 무결성 확인을 유지한다 — 기존 릴리스 계약. | 배포물에 필수 고지가 있고 기록된 무결성 정보와 일치하며 재빌드 결과가 재현된다. |
| 발행 전 컨테이너 검증과 소스에 일치하는 검증 기록을 요구한다 — 기존 발행 경계. | 검증되지 않았거나 소스가 다른 트리는 발행할 수 없다. |

#### 실패 보장

| 필수 보장 | 관찰할 결과 |
| --- | --- |
| Bun이 없으면 문서에 안내한 사용자 설치 단계로 해결하며 플러그인이 런타임을 자동 설치하거나 조용히 다른 런타임으로 전환하지 않는다. | 런타임이 없는 시작 시도는 소프트웨어 설치, 인증 정보 변경이나 대체 프로세스 실행 없이 실패한다. |
| 호환되지 않는 런타임, 검사 실패 또는 달라진 재빌드 결과에는 성공한 검증 기록을 발급하지 않는다. | 문제를 수정하기 전에는 해당 후보를 검증된 산출물로 발행할 수 없다. |

#### 노출 목록

| 필수 보장 | 관찰할 결과 |
| --- | --- |
| 어시스턴트는 인증된 원격 도구, 상태 조회가 있을 때의 제한된 대기와 로컬 제어를 보며, 업로드 티켓·소스 저장·작업공간 조회·워크플로 상태 조회 도구는 목록에 나타나지 않는다 — 승인된 목록 범위. | 연결된 목록에 내부 도구가 없고, 서버가 워크플로 상태를 제공하면 대기 도구는 계속 나타난다. |
| 내부 도구를 직접 호출하면 로컬에서 거부하고 서버로 보내지 않는다 — 승인된 목록 범위. | 내부 도구 이름으로 호출하면 원격 요청, 작업이나 과금 없이 알 수 없는 도구로 거부된다. |
| 작업공간 열기와 제한된 대기는 숨겨진 원격 조회를 통해 계속 동작한다 — 기존 로컬 제어 계약. | 준비된 작업공간 열기와 실행 대기는 각각 대응하는 내부 조회만 보낸다. |
| 이미 완료·실패했거나 실행 중이 아닌 실행을 기다리면 최신 상태를 바로 반환한다 — 상태 조회를 숨기기 위한 사용자 요구. | 이런 대기는 상태를 한 번 조회하고 멈추지 않으며 끝난 이유를 알려 준다. |
| 브리지는 묶음 도구와 action별 인수를 그대로 전달하고, 예전 작업별 이름의 별칭을 제공하지 않는다 — 서비스가 소유한 원격 구성. | 묶음 호출은 같은 action과 인수로 서버에 도달하고, 예전 이름은 로컬에서 알 수 없는 도구로 거부된다. |
| 연결, 연결 해제, 업로드, 작업공간 열기와 크레딧 페이지 제어는 이름과 인수 규칙을 유지한다 — 기존 로컬 제어 계약. | 이 제어들은 이전과 같은 입력을 받고 같은 입력을 거부한다. |
| 포함된 안내와 공개 문서는 노출된 묶음 도구, action과 로컬 제어만 영어와 한국어로 함께 설명한다 — 기존 이중 언어 문서 계약. | 어느 언어로 읽어도 같은 도구와 action을 설명하며, 숨겨진 이름이나 예전 이름을 호출 가능한 도구로 안내하지 않는다. |

## Alternatives

### Node.js로 통일

기존 런타임과 테스트가 함께 동작한다. 익숙한 필수 실행 환경을 유지하지만 사용자가 선택한 Bun 기반 실행·개발 환경을 충족하지 않는다.

### Bun 실행과 Node.js 개발 도구 병행

전환 범위를 줄이고 기존 테스트 실행기를 유지할 수 있다. 대신 두 런타임 환경이 필요하고 설치·빌드·검증 방식이 나뉜다.

### 작업공간 조회와 워크플로 상태 조회를 계속 노출

어시스턴트가 작업공간이나 실행 상태를 직접 조회할 수 있다. 두 조회는 이미 로컬 열기와 대기로 사용할 수 있으므로, 노출하면 목록 크기가 늘고 같은 조회에 진입점이 둘이 된다. 사용자는 숨기기로 했다.

## Consequences

고객은 플러그인을 활성화하기 전에 Bun을 설치하며, 기여자는 같은 런타임 계열로 개발과 검증을 진행한다. 실행 의존성을 번들에 포함하므로 의존성 준비는 발행자가 담당한다.

작업공간 조회와 워크플로 상태 조회를 숨기면 어시스턴트는 로컬 열기와 대기로만 이 조회를 사용한다. 상태 도구가 없는 서버에서는 대기도 제공하지 않는다. 원격 변경 후에는 예전 작업별 이름에 저장된 호스트 승인이 더 이상 맞지 않으므로 호스트가 다시 확인을 요청한다.

유지보수자는 런타임에 따른 테스트 주입과 번들링 차이를 처리하면서 기존 검증 조건과 고지를 보존해야 한다. Bun 버전을 올릴 때 메타데이터·문서·검증을 함께 맞춘다. 시작 시간과 초기 메모리는 호환성·설치 부담과 함께 관찰할 수 있는 지표이며 합격 기준값으로 사용하지 않는다.
