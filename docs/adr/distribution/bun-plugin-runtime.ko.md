# ADR 0001: Bun 기반 플러그인 설치와 배포

[English](0001-bun-plugin-runtime.md)

Date: 2026-11-07

## Status

Accepted (2026-11-12)

## Purpose

PixelbankStudio Plugin 사용자는 어시스턴트가 로컬 MCP 연결 프로그램을 시작하기 전에 필요한 실행 환경을 알아야 한다. 기여자는 같은 프로그램을 하나의 지원 런타임으로 빌드하고 검증할 수 있어야 한다. 사용자는 플러그인 실행과 개발 전반에 Bun을 사용하고, Bun이 없는 사용자에게 설치 방법을 안내하기로 했다.

이 결정은 독립적으로 배포하는 데스크톱 플러그인의 실행 환경과 배포 요구사항을 소유한다. 계정 권한, 창작 처리와 크레딧은 PixelbankStudio 원격 서비스가 소유한다.

## Decision Drivers

- 고객의 필수 실행 환경과 기여자의 검증 환경은 같은 런타임 계열을 사용해야 한다.
- 설치된 플러그인은 실행 의존성을 포함해 사용자가 런타임 설치 후 실행할 수 있어야 한다.
- 실행 환경 통일은 기존 인증·파일 보호·발행 검증을 보존해야 한다.
- 영어와 한국어 사용자에게 동등한 설치·복구 안내를 제공해야 한다.

## Decision

PixelbankStudio Plugin의 데스크톱 실행, 의존성 준비, 빌드와 검증에 Bun을 사용한다. 고객은 Bun을 먼저 설치한다. 독립 설치 패키지는 실행 번들, 스킬, 공개 도구 계약과 필수 고지를 포함한다.

개발과 자동 검증은 같은 기록된 Bun 버전을 사용한다. 지원 데스크톱 환경은 macOS와 Linux다. 기존 MCP와 비공개 파일 처리는 Bun의 호환 표준 라이브러리 API를 사용할 수 있으며, 런타임 선택으로 원격 서비스의 권한을 변경하지 않는다.

### 실시간 목록과 공개 계약

인증된 원격 목록이 현재 도구의 사용 가능 여부와 입력 스키마를 결정한다. 브리지는 호출을 전달하기 전에 현재 계약으로 인수를 검증하며, 스키마 파일이 기능이나 권한을 부여하지 않는다. 패키지의 공개 계약은 서비스의 공통 계약에서 생성해 오프라인 조회와 재현 가능한 릴리즈를 지원한다. 로컬 동기화는 서비스가 내보낸 공개 산출물을 읽고 패키지의 공개 계약만 갱신한다. 비공개 소스·시크릿·사용자 데이터를 가져오지 않으며, 설정한 원본과 불일치하면 검증을 실패시킨다. 서비스 체크아웃이 없어도 실시간 탐색은 사용할 수 있다.

서버가 대응하는 상태 조회를 제공하면 브리지는 읽기 전용 워크플로 대기를 제공한다. 대기 범위는 1–60초, 기본 30초이며 일반 조회 사이에 최소 5초를 두고 서버의 더 긴 간격과 재시도 거부 시간을 따른다. 대기 취소나 만료는 접수된 서버 실행을 계속 유지하고, 같은 실행 식별자와 마지막 관측 상태를 보존한다. 조회가 쓰기 작업으로 바뀌지 않는다.

### Requirement contract

#### 설치

| 필수 보장 | 관찰할 결과 |
| --- | --- |
| 지원하는 macOS·Linux 설치는 Bun으로 플러그인을 실행하며 Node.js 설치를 요구하지 않는다 — 승인된 실행 환경 범위. | Bun이 있고 Node.js가 없는 지원 기기에서 플러그인이 시작되고 기존 MCP 상호작용을 완료한다. |
| 설치 패키지는 실행 의존성을 포함한다 — 기존 독립 배포 계약. | 개발 체크아웃 밖에 복사한 패키지가 별도 의존성 설치 없이 시작된다. |
| 영문·한글 설치 안내는 Bun이 없을 때의 설치, 버전 확인과 호스트의 실행 파일 탐색을 설명한다 — 사용자의 명시적 요구. | 어느 언어로 읽어도 실행 환경 부재에서 실행 파일 확보와 플러그인 실행까지 진행할 수 있고, 서로의 언어로 이동할 수 있다. |

#### 검증과 발행

| 필수 보장 | 관찰할 결과 |
| --- | --- |
| 의존성 준비·타입 검사·빌드·테스트는 Bun으로 실행하며 검증 버전을 하나로 기록한다 — 승인된 개발 도구 범위. | Node.js 실행 파일이 설치되지 않은 새 검증 환경에서 전체 검사를 완료한다. |
| 런타임과 산출물 변경은 인증, 인증 정보 비공개 저장, 선택 파일 보호와 지원 프로토콜 동작을 보존한다 — 기존 플러그인 보장. | 설치 번들에서 기존 성공·거부 조건이 계속 성립한다. |
| 배포는 서드파티 고지와 번들·공개 계약의 무결성 확인을 유지한다 — 기존 릴리스 계약. | 배포물에 필수 고지가 있고 기록된 무결성 정보와 일치하며 재빌드 결과가 재현된다. |
| 발행 전 컨테이너 검증과 소스에 일치하는 검증 기록을 요구한다 — 기존 발행 경계. | 검증되지 않았거나 소스가 다른 트리는 발행할 수 없다. |

#### 실패 보장

| 필수 보장 | 관찰할 결과 |
| --- | --- |
| Bun이 없으면 문서에 안내한 사용자 설치 단계로 해결하며 플러그인이 런타임을 자동 설치하거나 조용히 다른 런타임으로 전환하지 않는다. | 런타임이 없는 시작 시도는 소프트웨어 설치, 인증 정보 변경이나 대체 프로세스 실행 없이 실패한다. |
| 호환되지 않는 런타임, 검사 실패 또는 달라진 재빌드 결과에는 성공한 검증 기록을 발급하지 않는다. | 문제를 수정하기 전에는 해당 후보를 검증된 산출물로 발행할 수 없다. |

## Alternatives

### Node.js로 통일

기존 런타임과 테스트가 함께 동작한다. 익숙한 필수 실행 환경을 유지하지만 사용자가 선택한 Bun 기반 실행·개발 환경을 충족하지 않는다.

### Bun 실행과 Node.js 개발 도구 병행

전환 범위를 줄이고 기존 테스트 실행기를 유지할 수 있다. 대신 두 런타임 환경이 필요하고 설치·빌드·검증 방식이 나뉜다.

## Consequences

고객은 플러그인을 활성화하기 전에 Bun을 설치하며, 기여자는 같은 런타임 계열로 개발과 검증을 진행한다. 실행 의존성을 번들에 포함하므로 의존성 준비는 발행자가 담당한다.

유지보수자는 런타임에 따른 테스트 주입과 번들링 차이를 처리하면서 기존 검증 조건과 고지를 보존해야 한다. Bun 버전을 올릴 때 메타데이터·문서·검증을 함께 맞춘다. 시작 시간과 초기 메모리는 호환성·설치 부담과 함께 관찰할 수 있는 지표이며 합격 기준값으로 사용하지 않는다.
