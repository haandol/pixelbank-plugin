# ADR 0001: 공개 크레딧 페이지를 통한 크레딧 부족 복구

[English](0001-credit-shortage-recovery.md)

Date: 2026-11-08

## Status

Accepted (2026-11-08)

## Purpose

요청한 작업에 필요한 크레딧이 부족한 사용자는 바로 충전하고 계속할 수 있어야 한다. 부족하다는 오류만 보여 주면 사용자가 구매 페이지를 직접 찾아야 한다. 사용자는 기본 브라우저 자동 열기와 대화의 클릭 가능한 링크 제공을 선택했다.

이 결정은 데스크톱 이동과 어시스턴트의 복구 안내를 소유한다. 가격·무료 사용·잔액·비용 승인·작업 접수는 원격 서비스가, 상품 선택·결제는 기존 웹사이트가 소유한다.

## Decision Drivers

- 크레딧 부족은 사이트 검색 없이 사용할 수 있는 복구 페이지로 이어져야 한다.
- 페이지 열기는 크레딧 구매와 처리 재전송과 구분되어야 한다.
- 브라우저를 열지 못해도 원래 오류와 사용할 수 있는 링크를 보존해야 한다.
- 이동에 임의 주소나 비공개 계정 정보를 사용해서는 안 된다.

## Decision

요청한 작업이 크레딧 부족으로 거부되면 PixelbankStudio 크레딧 구매 페이지를 기본 브라우저에서 열고, 오류 결과와 사용자에게 보내는 답변에 링크를 포함한다. 목적지는 정확히 https://www.pixelbankstudio.com/pricing이며 URL에 인증 정보·주문·작업 데이터를 넣지 않는다.

현재 계정 정보와 선택한 작업의 가격을 확인해, 사용할 수 있는 무료 횟수를 고려한 뒤에도 자금이 부족하다는 것이 분명하면 제출 전에도 같은 페이지를 열 수 있다. 크레딧 잔액 0만으로는 이 조건이 성립하지 않는다. 사용자가 크레딧 페이지 방문을 명시적으로 요청한 경우에도 전용 열기 기능을 사용할 수 있다.

### Requirement contract

#### Required guarantees

| 필수 보장 | 관찰할 결과 |
| --- | --- |
| 크레딧 부족으로 확정된 처리 거부는 고정된 구매 페이지를 자동으로 열고 클릭 가능한 링크를 유지한다 — 승인된 사용자 복구 동작. | 거부된 이미지 요청이 크레딧 상품 페이지를 열며 답변에 링크가 있다. |
| 목적지는 정확히 https://www.pixelbankstudio.com/pricing이며 호출자·제공사의 입력 대신 로컬에서 정한다 — 신뢰할 이동 경계. | 다른 URL이나 제공사의 복구 주소로 열리는 페이지를 바꿀 수 없다. |
| 제출 전 복구는 무료 사용 우선순위를 보존하며 요청한 작업의 현재 필요 금액을 확인한다 — 기존 크레딧 계약. | 잔액 0이어도 무료 사용이 가능하면 작업을 계속할 수 있고, 자금이 부족한 작업은 처리 제출 없이 구매 페이지로 이동할 수 있다. |
| 답변은 페이지를 연 결과와 충전 성공을 구분한다 — 복구 상태의 권위. | 페이지를 열었다는 결과만으로 크레딧이 추가됐다고 안내하지 않는다. |
| 영문·한글 안내는 같은 복구·계속하기 단계를 설명한다 — 기존 양언어 고객 지원. | 어느 언어로 읽어도 구매 페이지·직접 결제·이후 잔액 확인을 안내받는다. |

#### Prohibitions

| 필수 보장 | 관찰할 결과 |
| --- | --- |
| 이동은 결제 세션 생성·상품 선택·결제 승인·크레딧 지급·새 처리 요청을 수행하지 않는다 — 기존 동의 경계. | 페이지 열기로 잔액이 바뀌거나 결제 주문·처리 작업이 만들어지지 않는다. |
| 자금 복구는 거부되거나 결과가 불확실한 작업을 자동 재전송하거나 작업 키·승인 예산을 바꾸지 않는다 — 기존 작업 연속성. | 나중에 사용자가 계속할 때 원래 요청을 유지하고 현재 잔액·가격·승인을 확인한다. |
| 무료 사용 조회 실패·가격 변경·비용 승인 누락을 크레딧 부족으로 확정하지 않는다 — 기존의 서로 다른 복구 조건. | 해당 결과는 동의·견적 안내를 유지하며 구매 페이지를 자동으로 열지 않는다. |

#### Failure guarantees

| 필수 보장 | 관찰할 결과 |
| --- | --- |
| 브라우저를 열 수 없어도 원래 크레딧 오류·확인된 비용 정보·고정 복구 링크를 유지한다 — 링크 대체 경로. | 열기 실패 뒤에도 부족 오류와 사용할 수 있는 구매 링크가 있으며, 열기 실패와 충전 성공을 구분한다. |

## Alternatives

### 대화 링크와 요청 시에만 열기

데스크톱 제어가 없는 호스트에서도 링크를 사용할 수 있고 자동 브라우저 동작을 줄인다. 이미 막힌 사용자에게 추가 복구 단계가 필요하며, 사용자는 자동 열기와 링크 제공을 선택했다.

### 이동 주소 없는 오류 문구

브리지를 가장 작게 유지할 수 있지만 사용자가 충전 위치를 찾아야 하므로 요청한 복구를 충족하지 않는다.

## Consequences

도구 호출 중 크레딧 부족 복구가 기본 브라우저를 열 수 있다. 사용자가 별도로 반복한 요청이 각각 부족으로 거부되면 페이지가 더 열릴 수 있지만, 브리지는 자동 재시도로 해당 요청을 만들지 않는다.

데스크톱 열기가 불가능해도 링크를 사용할 수 있다. 사용자는 웹사이트에서 상품을 선택하고 결제를 마친 뒤 계속하기를 요청한다. 페이지를 열었다는 결과는 자금 변경의 근거가 아니다.
